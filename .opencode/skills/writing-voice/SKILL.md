# Writing Voice

## Tone

First person. Conversational. Like talking to a friend who also codes. Midhun writes about himself, not about "the candidate" or "the developer."

## Rules

1. **No corporate filler words.** Never use: leverage, seamless, passionate, innovative, cutting-edge, synergy, robust, scalable, bespoke, world-class, empowered, harness, leverage, streamline, disruptive, solutions-driven, thrive, delve.

2. **Short sentences.** If a sentence is over 25 words, split it.

3. **Specific, not generic.** "Built a FIFA prediction platform with 737+ bets" beats "Developed a full-stack web application with complex features."

4. **Prose over bullet points** for bio paragraphs and about sections. Use bullet points only for lists of technologies, features, or items that are genuinely list-shaped.

5. **No superlatives without proof.** Don't say "amazing" or "incredible" unless backed by a number or specific detail.

6. **Active voice.** "I built X" not "X was developed."

7. **Show, don't tell.** Instead of "I'm passionate about AI," say "I run quantized 8B LLMs on a laptop GPU for fun."

## Examples

Good:
> "I built WC Predict '26 for IEEE Sahrdaya — 58+ players, 737+ bets, live leaderboard."

Bad:
> "I developed a robust, scalable prediction platform that seamlessly integrates multiple features."

Good:
> "I'm a CS sophomore at Sahrdaya building AI systems and self-hosted infra."

Bad:
> "I am an innovative and passionate full-stack developer with experience in cutting-edge technologies."

## Project Descriptions

Format: one sentence that says what it is, one sentence that says what makes it interesting. Use the actual tech stack. Mention real numbers when available.

Example from the current data:
> "Autonomous AI agent for Kochi Metro — route planning, GPS lookup, Razorpay bot-evasion ticket booking, WhatsApp alerts."

## Metadata & SEO Copy

- `title` format: `"Page Title | Midhun P M"`
- `description`: 120-160 chars, factual, no clickbait. Include what the page is about and who it's for.

## Blog Posts

- Write like you're explaining something to a peer.
- Use "I" not "we" unless co-writing.
- Start with the problem, then the approach, then what happened.
- Code examples are encouraged. Theory without code is boring.
- No "In this blog post, we will explore..." intros. Just start.
